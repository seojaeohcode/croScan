# 17. 본 발표 시연 영상: 사용자 흐름을 반영한 장면 콘티 초안

작업반장이 정보를 보완해 제출하고, 안전관리자가 작업 간 위험을 검토해 조율 문안과 현장 전달 자료를 준비하는 흐름입니다. 사용자가 작성한 0~22번 장면을 바탕으로 정리했습니다.

- 작성일: 2026-11-02
- 상태: **사용자 장면 방향 반영 · 촬영 전 콘티 초안**. 실제 입력·응답·배포 화면은 아직 리허설하지 않았습니다.
- 시간: 영상 길이를 먼저 정하지 않습니다. 장면의 필요성을 검토한 다음 줄입니다.
- 대표 사례 권장: `6733 화기 허가서 × WP-1029-01 E42P 블록 도장 터치업`.
- 범위: 영상 구성과 준비 자료. 화면 기능을 추가로 설계하거나 제품 코드를 수정하지 않습니다.
- 제작 형식: 사용자가 지정한 [작업반장 참고 GIF](https://github.com/seojaeohcode/croScan/blob/main/docs/images/demo_foreman.gif)의 **실제 화면 → 핵심 부분 확대·강조 → 하단 자막** 방식을 사용합니다. 장면 길이는 별도로 결정합니다.

**이 문서에서 알 수 있는 것**

- 사용자의 23개 장면이 하나의 이야기로 이어지는 순서
- 각 장면에서 보여 줄 기능과 장점
- 긴 답변 뒤 오타 입력을 비교하는 연출과 실제 기능에 맞춘 표현
- 촬영 전에 준비할 원본·답변·출력물과 다음 작업

## 1. 무엇을 보여 주나

> 작성된 서류에서 시작해, 애매한 정보를 반장의 말로 보완합니다. 보완한 정보로 작업 자체의 위험을 검토하고, 다른 팀 작업과 함께 봐야 드러나는 위험을 확인합니다. 안전관리자는 필요한 사람에게 조율을 요청할 문안과 현장 전달 자료를 준비합니다.

본편의 다섯 흐름입니다.

| 묶음 | 사용자 장면 | 시청자가 이해할 것 |
|---|---|---|
| 시작 자료 | 0~3 | 기존 계획서와 허가서로 시작하고, 이번에는 왜 화기 사례를 보는가 |
| 반장의 말과 정보 보완 | 4~7 | 자연스럽게 답한 내용을 분리해 확인·반영하고 중요한 기재를 다시 살핀다 |
| 개별 위험 검토와 제출 | 8~10 | 작성된 위험 기재 외에 검토할 항목·준비 계획을 보완해 전달한다 |
| 여러 작업의 종합 검토 | 11~16, 18 | 다른 팀 작업과 겹치는 시간·위치·위험 경로를 확인한다 |
| 조율과 현장 전달 자료 | 17, 19~22 | 경보를 본 뒤 누구에게 무엇을 요청하고 어떤 자료로 전달할지 이어진다 |

## 2. 왜 이렇게 묶나

이야기의 연결점은 화면 이름이 아니라 **같은 작업 정보가 다음 검토에 쓰이는 모습**입니다.

- 계획서 종류 소개는 서식 차이를 보여 준 뒤 시간·위치가 한 목록으로 정리되는 모습에 연결합니다.
- 허가서 종류 소개 뒤에는 6733의 원본 시간·장소를 보여 주며 사례를 고른 이유를 설명합니다.
- 답변 해석 뒤에는 실제 반영된 결과를 보여 줍니다. 카드만 보여 주고 끝내지 않습니다.
- 제출과 역할 전환 사이에서는 같은 `6733` 작업이 안전관리자에게 이어지는지 보여 줍니다.
- 배치도는 목록과 별개 기능 소개로 끊지 않고, 같은 E42P 작업 쌍의 위치를 확인하는 장면으로 연결합니다.
- 메시지와 별지는 서로 다른 일을 합니다. 메시지는 조율 요청용이고, 별지는 현장에 전달할 작업 간 조건을 정리하는 자료입니다.

사용자가 정한 편집 순서는 **18번 배치도 → 17번 메시지**입니다. 위험 상세 → 배치 맥락 확인 → 조율 요청 문안 복사 → 현장 전달 자료 순서로 이어집니다. 원안 번호는 대조를 위해 유지합니다.

함께 반영한 장면 방향입니다.

- **4번:** 「일상적으로 이렇게 길게 답해도 됩니다」. 여러 정보가 섞인 구어체 답변을 입력합니다.
- **5번:** 「그런데 오타가 섞이면 어떨까요?」. 같은 정보에 오타가 있는 입력을 비교하고 핵심 정보가 정리되는 실제 결과를 보여 줍니다.
- **9번:** 대표 항목은 자세히 보여 주고, 나머지 반복 확인은 줄여 완료 상태로 연결합니다.
- **17번:** 실제 외부 전송을 촬영하지 않는 경우 「보냈다」가 아니라 「문자를 복사했다」로 설명합니다.

### 3.1 장면 1의 「작업계획서 종류」

허가서의 5개 작업 유형과 구분합니다. 여기서는 **본청과 협력사가 서로 다른 서식으로 제출한 계획서**를 보여 줍니다. 업체·양식 목록을 외우게 하기보다 「다른 형식의 자료도 작업명·시간·위치로 모아 검토한다」에 초점을 둡니다.

촬영 준비자는 어떤 계획서를 실제로 올리고 확인했는지 기록합니다. 반장이 모든 자료를 자동 확인한 것처럼 편집하지 않습니다.

### 3.2 장면 4와 5의 답변

4번은 여러 사실이 섞인 일상적인 긴 답변을 보여 주는 **기본 테이크 A**입니다. 전환 문구 후보는 「현장에서는 정보를 하나씩 나눠 말하지 않습니다. 이렇게 한 번에 답하면 어떨까요?」입니다.

> 작업은 오후 1시부터 3시까지 해요. 장소는 3BAY 08~10칼럼 E42P 블록 상부고요. 아크 가우징하고 CO2 용접할 예정입니다.

5번은 「그런데 오타가 섞이면 어떨까요?」라는 질문 뒤 **같은 사실**을 오타·띄어쓰기 변형으로 적는 **비교 테이크 B**입니다. 두 장면을 모두 본편에 넣는 방향입니다. 아래는 리허설 후보이지 처리 성공을 확인한 문장이 아닙니다.

> 실제 자겁은 오후 1시부터 3시까지에요. 장소는 3BAY 08~10칼럼 E42P 블록 상부구요. 아크 가우징 하고 CO2 용접 할 예정임니다.

- 중요한 시간·BAY·칼럼·블록·공법 식별자는 바꾸지 않습니다.
- 오타 이해와 장문에서 여러 정보를 찾는 것은 다른 기능입니다. 긴 글을 처리했다고 오타 복원 성능이 입증된 것은 아닙니다.
- 같은 세션에서 이미 확인한 답을 다시 넣어 중복 답·정정 질문을 만드는 대신, 깨끗한 동일 시작 상태에서 별도 촬영합니다.
- 두 테이크를 「기본 입력 → 그런데 오타가 있다면? → 비교 결과」로 연결합니다. 같은 내용을 두 번 답하는 하나의 연속 대화처럼 편집하지 않습니다.
- 리허설로 5번의 입력 문장과 실제 정리 결과를 고정합니다. 성공하지 않은 입력의 처리 결과를 만들어 넣지 않습니다. 검증한 예시의 시간·위치·공법을 읽는 모습을 보여 줍니다.
- 일반적인 오타를 모두 자동 교정한다고 주장하지 않습니다. 원문 오타를 지우는 기능과 원문에서 필요한 정보를 읽는 기능을 구분합니다.
- 여러 질문이 아직 열려 있어야 다른 질문의 답 제안이 가능합니다. 실제 시작 질문과 열린 질문을 기록합니다.

### 3.3 장면 7의 팝업과 장면 10의 PDF

팝업 이동은 [05c 수정안](05c_핵심정보_확인팝업_이동_수정안.md)의 내용입니다. 실제 촬영본에 적용됐는지 확인합니다. 반영 전 배포본을 촬영하면서 팝업이 이미 3단계로 이동한 것처럼 보여 주지는 않습니다.

PDF에서는 다음을 구분해 보여 줍니다.

1. 원본 파일은 별도로 보존됩니다.
2. 사전검토 반영본은 원본 양식의 보충 내용을 확인할 수 있는 출력입니다.
3. 추가검토서는 양식 밖 답과 미확인 사항 등을 담습니다.

추가검토서가 꼭 한 쪽이라는 보장은 없습니다. 실제 자료를 출력해 페이지 수를 확인하고, 영상에서는 반영본 한 쪽과 추가검토서의 대표 내용을 선택합니다. 전체 답을 한 쪽에 맞추기 위해 중요한 내용을 삭제하지 않습니다.

### 3.4 장면 17과 21의 서로 다른 역할

- **일정 조율 메시지:** 두 반장이 작업 시간·순서를 협의하도록 요청할 문안입니다. 복사로 실제 전송이나 협의가 완료되지는 않습니다.
- **현장 게시 별지:** 해당 작업에 필요한 조정·착수·중지 조건을 읽을 수 있는 자료입니다. 서류 발행은 실제 현장 게시·착수 승인과 다릅니다.

실제 합의 결과를 입력·반영한 장면이 없다면 「조율이 완료된 일정표」를 출력했다고 설명하지 않습니다. 이번 촬영에서는 앱이 실제로 만든 문안과 조건을 확인해 발행하는 범위까지만 보여 줄 수 있습니다.

### 3.5 참고 GIF를 적용한 화면 연출

사용자가 지정한 GIF의 조회 시점 파일을 확인했습니다. 규격은 960×600, 프레임 80개, 한 순환의 재생 시간은 약 89.94초입니다. 이 수치는 참고 파일의 특성입니다. 새 영상의 목표 길이나 분량 기준으로 삼지 않습니다.

참고 파일에서 확인한 형식입니다.

- 전체 화면을 보여 주어 현재 단계와 위치를 알립니다.
- 관련 입력·해석·출력 부분으로 확대해 읽을 곳을 좁힙니다.
- 주황색 테두리로 현재 설명하는 곳을 표시합니다.
- 하단 남색 띠에 단계 제목과 짧은 설명을 표시합니다.
- 화면 전환·확대 사이에 읽을 수 있는 정지 구간을 둡니다.

새 영상은 이 시각 형식을 따르되 기능 설명을 나열하지 않습니다. 같은 작업의 입력 → 해석 → 검토 → 요청 → 출력 관계가 자막과 장면 연결에서 이어져야 합니다.

| 구간 | 전체 화면에서 알려 줄 것 | 확대할 곳 | 자막 방향 예시 |
|---|---|---|---|
| 0~3 | 반장 역할과 계획서·허가서 검토 단계 | 서로 다른 양식의 작업 정보, 6733의 시간·장소 | 「기존 서류에서 시작합니다」 / 「적혀 있어도 실제 작업 정보는 모호할 수 있습니다」 |
| 4 | 현재 질문과 입력 위치 | 긴 답변의 시간·위치·공법 | 「여러 내용을 한 번에 답합니다」 |
| 5 | 같은 정보에 오타가 섞인 비교 입력임 | 오타가 있는 원문과 실제로 읽힌 값 | 「그런데 오타가 섞이면?」 → 리허설로 확인한 결과 한 문장 |
| 6~7 | 해석 확인과 다음 단계 연결 | 원문·목적지·반영 결과, 핵심 정보 확인 창 | 「원문과 들어갈 곳을 보고 확인합니다」 / 「넘어가기 전 핵심 정보를 다시 살핍니다」 |
| 8~10 | 개별 위험 검토와 제출 완료 | 불티·화재 항목, 준비 조치, 반영본과 추가검토서 | 「작성된 위험 외에 검토할 항목을 보완합니다」 |
| 11~16 | 관리자 역할과 하루 작업·순위 | 6733×WP-01, 겹치는 시간 막대·위험 경로 | 「다른 팀 작업과 함께 보면 겹치는 위험이 드러납니다」 |
| 18 | 같은 쌍을 고른 배치도 | 해당 시각·BAY·칼럼·E42P 작업 | 「같은 시각의 작업 위치를 함께 확인합니다」 |
| 17 | 조율 메시지 화면 | 받는 반장·협의 상대·겹치는 구간·본문·복사 | 「누구에게 무엇을 요청할지 문안을 준비합니다」 |
| 19~22 | 같은 작업의 서류 발행·결과 | 우리 반이 할 일·착수·중지 조건 | 「현장에서 필요한 조건을 전달할 자료로 정리합니다」 |

연출 규칙입니다.

1. 화면이 처음 바뀔 때는 현재 위치를 파악할 수 있게 보여 준 뒤 확대합니다. 계속 확대된 화면만 이어 붙이지 않습니다.
2. 확대는 한 장면에서 읽을 대상 하나를 중심으로 합니다. 시간·위치·근거·버튼을 동시에 모두 강조하지 않습니다.
3. 긴 답변 입력과 오타 비교는 실제 입력·처리 화면을 촬영합니다. 중요한 입력·응답 변화는 정지 캡처만으로 성공한 것처럼 만들지 않습니다.
4. 반복 확인과 대기는 줄일 수 있지만, 결과를 실제 처리 속도나 자동 완료 성능으로 오인하게 편집하지 않습니다.
5. 하단 자막은 단계 이름과 의미를 짧게 씁니다. 같은 UI 문구를 길게 읽기보다 사용자의 수고가 어떻게 줄었는지 설명합니다.
6. 긴 원문을 읽는 화면에서는 충분히 확대하고 자막이 필요한 정보를 가리지 않도록 합니다.
7. 참고 GIF의 기존 작업 값·결과·오래된 화면 상태를 새 시연 결과로 재사용하지 않습니다. 촬영용 사례의 실제 화면으로 교체합니다.

발표 재생용 원본은 MP4로 제작하고, 필요하면 공유용 GIF를 따로 만듭니다. 영상 비율은 발표 슬라이드에 맞추고, 기본 제작 후보는 1920×1080입니다. 참고 파일 960×600을 단순 확대해 최종 영상으로 쓰기보다 촬영 화면을 충분한 해상도로 확보합니다. 음성·음악 여부는 아직 정하지 않았습니다.

## 5. 촬영 전 확인

지금은 촬영 순서와 장면의 주장을 정한 단계입니다. 다음 작업은 아래 순서입니다.

1. 장면 3~7에 사용할 실제 질문과 구어체 답변을 먼저 리허설합니다.
2. 테이크 A/B 각각의 해석 결과와 남은 질문을 기록합니다. 오타 버전은 성공을 전제하지 않습니다.
3. 체크리스트 대표 항목과 나머지 답을 정리해 같은 제출본을 만듭니다.
4. 안전관리자 화면에서 해당 제출본, 위험 쌍, 겹침 시간, 배치도 위치가 이어지는지 확인합니다.
5. 조율 문안과 발행 출력물을 실제로 열어 최종 촬영용 자료를 확인합니다.
6. 장면마다 「입력 데이터 / 화면에 실제로 나온 결과 / 전체 화면과 확대할 곳 / 하단 자막 / 내레이션 한 문장」을 붙여 촬영 대본으로 발전시킵니다.
7. 촬영 후 반복 클릭·대기·역할 이동의 비중을 보고 줄입니다. 핵심 과정이 생략됐는데 자동으로 처리한 것처럼 소개하지 않습니다.

현재 강조할 장면은 **4·5·6·8·16·17·21**입니다. 4~6번은 「일상적인 긴 답변도 정리 → 오타가 섞이면? → 실제로 읽은 정보를 확인·반영」의 연결로 구성합니다. 9번 반복 확인은 축약하고, 18번은 17번 앞에 둡니다. 초 단위 분량은 아직 정하지 않습니다.

## 6. 한계

- 구어체·오타 문장의 실제 처리, 질문 순서, 최신 판정 개수·쌍 번호, 출력 페이지 수는 아직 촬영 환경에서 확인하지 않았습니다.
- 현재 문서 작성에서는 앱 상태·실제 연락·문서 발행·코드를 변경하지 않았습니다.
- 「오타가 어떤 형태든 처리됨」, 「모든 위험 탐지」, 「자동 전송·일정 조정·승인」은 이번 영상으로 주장하지 않습니다.
