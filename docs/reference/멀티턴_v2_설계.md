## 0. 한 줄 요약

반장이 허가서를 올리면 **꼭 필요한데 비었거나, 뜻이 모호하거나, 서로 맞지 않는 것만** 하나씩 묻는다. 다 물으면 항상 이렇게 끝낸다.

> 「추가로 말씀하실 게 있나요? 없으면 제출해 주세요.」

자유 답변에서는 필요한 값만 뽑는다. 그 값 때문에 새로 생긴 질문만 묻고, 다시 같은 문구로 끝낸다. 반장이 「없음 · 제출」을 누르면 제출본 PDF가 만들어진다.

```
허가서 업로드 ─▶ 규칙으로 질문 목록 계산 (반장이 이미 적은 것·앞에서 답한 것을 먼저 씀)
                    │
          ┌─────────▼─────────┐
          │ 남은 질문 있음?     │──예──▶ 한 가지 질문 ─▶ 버튼/짧은 입력 ─▶ 답을 사실 저장소에 넣고 다시 계산
          └─────────┬─────────┘                                         (모름 → "미정으로 남깁니다" 1회, 다시 안 물음)
                    │아니오
                    ▼
     「추가로 말씀하실 게 있나요? 없으면 제출해 주세요.」 [없음 · 제출]  + 입력칸
           │ 자유 답변                                   │ 없음
           ▼                                             ▼
   값 추출(시간·위치·번호·개수·높이·가스·병행 등)      제출본 PDF(원본 + 추가검토서 2쪽)
   "반영했습니다: …"                                    전산(HI-SES) 등록은 지금처럼 반장이 직접
   새 질문(처음 묻는 항목만)·상충 질문 ─▶ 다시 위 루프
```

## 1. 원칙

1. **당일 칸은 묻지 않는다** [확인]
   - 대상: 현장 안전조치, 추가정보의 체크와 수치(작업높이·중량·정격하중·정격전압 등).
   - 근거: 양식에 「작업당일 작업시작 전 체크(대면접수시 작성금지)」라고 적혀 있다(조사 PDF p405~412). 조사 PDF p4의 작성 시점표도 같다.
2. **예정 작업조건은 묻는다** [확인]
   - 대상: 공법·가스·진입 방식·회수 계획.
   - 근거: 신청 시 「4. 유해위험요소 및 추가전달사항: 밀폐공간 출입·가스 사용 등 예정된 작업조건」을 적게 되어 있다(p4).
   - 답은 계획으로만 기록한다. 조치를 했다는 증빙으로 바꾸지 않는다.
3. **ASK / SKIP / DEFER로 나눈다** [확인] (조사 PDF 각 작업의 2.7절)
   - **ASK**: 지금 필요한 것이 비었거나, 뜻이 모호하거나, 서로 맞지 않거나, 조건이 맞는 참고값과 설명 안 된 차이가 있을 때.
   - **SKIP**: 이미 충분하거나, 참고 범위와 겹치거나, 이미 설명을 받았을 때. 아직 때가 아닌 실제 증빙도 SKIP한다.
   - **DEFER**: 모름, 모델이 맞지 않음. 2쪽 「안전팀 확인」으로 넘긴다.
   - 질문 상태는 위험 판정이 아니다.
4. **정밀값은 요구하지 않는다** [확인]
   - 대상: 좌표, 질량, 풍량, 농도, 회로, 절단선 치수.
   - 근거: 각 작업 2.5절 「반장에게 전부 수기로 요구하는 목록이 아니다」.
5. **판단할 수 없는 로직은 넣지 않는다** [확인]
   - 허가구분, 2중점검, 승인권한은 누가 정하는지 미확인이다(p16). 그래서 묻지도 판정하지도 않는다.
   - 가상 공장 F01의 12m 축간격·크레인·회로 배치는 실제 값으로 쓰지 않는다.
6. **반장 부담을 최소로 한다** [추정]
   - 질문은 한 번에 하나다. 비슷한 것은 합쳐 묻는다(위치 + 블록 번호, 개수 + 공법).
   - 한 답이 다른 질문도 닫는다. 모든 답과 자유 답변을 사실 저장소 하나에 모은다.
   - 계산은 규칙으로 한다. LLM 호출은 없다(서버 CPU의 Raon은 한 번에 수십 초 걸린다).

## 4. 시간 적합도 (T6) [추정: 참고값은 조사 PDF 2.6절 작성자 추정]

비교하는 조건 (모두 맞아야 한다)
1. 작업이 하루다. 여러 날이면 비교하지 않는다. 날마다 준비·정리 횟수가 달라 같은 양이 아니기 때문이다.
2. 시간의 뜻이 확인됐다. 종일 시간이면 T1 답이 있어야 한다. 인양의 "움직이는 시간"은 단계 시간이라 전체 참고와 비교하지 않는다.
3. 모델 조건이 맞는다. 범위, 개수, 공법을 안다. 개수를 모르면 1개로 채우지 않는다.
4. 신청 시간과 참고 범위가 겹치지 않는다. 끝값도 겹침에 넣는다. 겹치면 묻지 않는다.

- 차이는 질문할 이유일 뿐이다. 오류나 위험으로 보지 않는다.

## 5. 공간 적합도 (L7) [추정]

- 칼럼 범위는 미터로 바꾸지 않는다. 구간 수로만 본다. F01의 12m 간격은 합성값이라 실제 공장에 쓰지 않는다.
- 국부 작업 하나의 활동 구역은 축 방향으로 최대 약 4m다(loto p353). 축 경계를 걸치면 2구간이 될 수 있다.
- 그래서 **대상 하나 + 3구간 이상**일 때만 그 범위의 뜻을 묻는다. 뜻은 다음 중 하나다: 작업 위치 / 이동 / 회수 / 접근 경로.
- 블록을 여러 개 적었거나 러그 개수가 여럿이면 넓은 범위가 설명된 것으로 본다. 이 경우 묻지 않는다(height S-ARRAY).
- 대조립 공장 모델의 표기도 읽는다: `2B`, `2B-08`, `2B / 08~12축`, 크레인 `CR-2B`.

## 6. 자유 답변 읽기 [추정]

- 읽는 값:
  - 시간대, 위치(공장·BAY·칼럼·축), 블록·설비·크레인 번호
  - 개수(개·EA·군데·곳·장), 높이(m)
  - 가스, 병행작업, 블록 안 작업, 공동인양·반전, 거더·상부 접근
- **부정과 조건은 구절 단위로 본다.**
  - 「가스는 안 쓰고 용접만」: 가스는 아님, 용접은 맞음.
  - 「다른 작업 없으면 시작」: 조건문이라 확정하지 않는다. B3은 그대로 둔다.

- 허가서가 여러 건인 파일이면 자유 답변이 어느 건 이야기인지 알 수 없다. 이때는 원문만 각 장에 붙이고 값으로 쓰지 않는다.
- 뽑은 값은 채팅에 「반영했습니다: 위치 3BAY 12칼럼 · 번호 OH-21-01」처럼 보여 준다.

## 7. 반복 방지·종료 [추정, 무한루프 없음]

- 질문 키는 `항목ID:승인번호`다. 한 허가서에서 같은 항목은 **한 번만** 묻는다. 답이 값을 바꿔도 같은 유형은 다시 묻지 않고, 바뀐 값은 2쪽에 반영한다.
- 「모름」에는 "미정으로 남기겠습니다. '안전팀 확인'에 넣었습니다."라고 1회 안내한다. 같은 항목은 다시 묻지 않는다.
- 형식 오류는 1회 다시 묻는다. 두 번째도 틀리면 원문 그대로 '미확인'으로 둔다.
- 자유 답변으로 새 키가 안 생기면 질문 없이 「반영했습니다…」와 마무리 문구를 보인다. 질문 항목 수가 유한해서 대화는 반드시 끝난다(시험: 10건 모두 '모름'으로 답 → 0~6번 묻고 종료).
- 「없음 · 제출」이나 "없어요·없습니다" 입력이면 바로 제출본을 만든다.

## 12. 코드리뷰(high)와 현장 대비 수정 (2026-10-27)

멀티턴 v2 코드(`augment.py`, `addendum.py`, `app.js`, `app.py`)를 리뷰해 현장에서 터질 수 있는 10건을 고쳤다. 서버 시험 100/100, 1993/1993, 7/7이고 운영에 배포했다.

- **시간 읽기** (`time_ranges`)
  - 「오후 2시~4시」, 「9시 30분」, 「9시 반」, 전각 물결(～ ∼)을 읽는다.
  - 오전·오후 없이 「1시」~「5시」라고 쓰면 대조립 주간 근무의 오후로 본다. 「01:00」처럼 0을 붙였거나 「새벽」이라고 쓰면 그대로 둔다.
  - 「12-14 칼럼」, 「10-27」, 「2-3개」는 시간이 아니다.
- **날짜**: 날짜 칸이 「10/27」처럼 ISO 형식이 아니어도 오류 없이 넘어간다. 전에는 /api/augment가 500으로 멈췄다.
- **번호**: CO2·N2·O2 같은 가스와 AH36·SS400 같은 강재는 블록 번호가 아니다. 그래서 「CO2 용접」만 적힌 허가서에도 D1을 묻는다.
- **다른 팀 이야기**: 자유 답이나 B3·C5 답에 나온 다른 팀의 장소·블록·개수·높이는 이 허가서 값으로 쓰지 않는다(`own_text`). 원문은 2쪽에 그대로 남긴다.
- **높이**: 「반경 5m」, 「이격 3m」는 거리라서 높이로 보지 않는다.
- **화면 (app.js)**
  - 연결이 끊기면 답을 그대로 두고 「다시 시도」 버튼을 보인다.
  - 응답을 기다리는 동안에는 입력을 잠가서 같은 질문에 두 번 답하지 못하게 한다.
  - 늦게 도착한 옛 응답은 버린다.
  - 「제출」, 「아니요, 없습니다」, 「이상 없음 제출할게요」, 「끝」으로도 마무리된다. 「다른 작업 없음」처럼 내용이 있는 말은 그대로 읽는다.
- **서버 (app.py)**
  - 형식이 맞지 않는 답은 걸러 낸다.
  - 같은 질문의 답이 두 번 오면 마지막 것 하나만 쓴다.
  - 잘못된 제출 내용이나 열 수 없는 PDF에는 500 대신 400과 안내 문구를 돌려준다.

## 13. 애매하면 다시 묻기 (2026-10-27, 사용자 요청)

> "2시라고 하면 2시인지 14시인지 모르니까 다시 물어봐라. 시간 말고도 AI가 봤을 때 이해 안 가는 건 그냥 넘어가지 마라. 그렇다고 무한루프는 안 되게."

croScan은 짐작해서 값을 채우지 않는다. 두 가지로 읽히거나 알아듣지 못한 말은 한 번 되묻고, 되묻기에는 끝이 있다.

| 경우 | 예 | croScan이 하는 일 |
|---|---|---|
| 오전·오후가 없는 1~6시 | 「2시~4시」 | A1: 「오후 14:00~16:00」「새벽·오전 02:00~04:00」「모름」 버튼으로 묻는다. 답하기 전에는 그 시간을 쓰지 않는다 |
| 날짜가 정해지지 않은 말 (여러 날 허가서) | 「내일 9시~11시」 | A2: 날짜 버튼(10월 27일…)과 「날마다 같음」으로 묻는다 |
| 숫자 없는 시간 (자유 답) | 「오후에 해요」 | A3: 몇 시부터 몇 시까지인지 묻는다 |
| 아무것도 읽지 못한 자유 답 | 「그건 좀 그래요」 | U1: 「작업 시간」「작업 장소」「다른 팀 작업」「참고로만 남김」 중 무엇에 대한 말인지 묻는다 |
| 읽을 수 없는 입력 답 | 「저쪽」「2~3개」「천장크레인 한 대」「ㅇㅇ」「상황 봐서」「아마 6개」 | 무엇이 안 읽혔는지 말하고 한 번 다시 받는다. 두 번째에도 안 되면 적은 그대로 남기고 안전팀 확인(미확인)으로 넘긴다 |
| 확실하지 않은 말 (자유 답) | 「아마 없을 거예요」 | 값으로 확정하지 않는다. 앞의 답과 어긋나면 상충 확인(C5)은 한 번 한다 |
| 버튼 대신 짧게 친 답 | 「없어요」「몰라요」「네」 | 같은 뜻의 버튼으로 받는다. 그런 버튼이 없으면 버튼으로 골라 달라고 한다(「없어요」가 「있음」의 내용으로 들어가지 않게) |
| 마무리에서 「네」만 침 | 「네」 | 더 적을 내용을 적거나 「없음 · 제출」을 누르라고 안내한다 |

- 7~12시는 주간 근무 시간으로 읽고 묻지 않는다. 「09:00」처럼 0을 붙였거나 13시 이상이어도 묻지 않는다.
- 끝 시각은 시작보다 뒤인 쪽으로 읽는다(「11시~1시」 → 11:00~13:00).

**무한루프 방지**
- 같은 질문은 한 번만 묻는다(질문 키).
- 못 읽은 답은 한 번만 다시 받는다.
- 되묻기 질문(A1·A2·A3·U1)은 버튼으로 답하거나, 한 번만 검사하는 입력으로 답한다.
- 되묻기는 허가서 한 장에 최대 3번(`ASK_BACK`)이다. 그 뒤의 애매한 말은 묻지 않고 2쪽 「안전팀 확인」에 '확인 못 한 말'로 적는다.
- 시험(`stubborn`): 10건 모두에서 모든 질문에 애매한 답을 하고 알아들을 수 없는 자유 답을 6번 더 넣었다. 그래도 10~16단계 안에 끝났고, 되묻기는 3번을 넘지 않았으며, 같은 질문은 반복되지 않았다.

**시험·배포 (13절 첫 배포)**: 반장 질문 141/141, 허가서 추출 1993/1993, 작업계획서 7/7로 통과했고 운영에 배포했다(asset v=20261027f). 최종 수치는 14절에 있다. 운영 화면에서 다음을 확인했다.
- 「2시~4시」 → A1 → 「오후」 → 14:00~16:00
- 「저쪽」 → 다시 받음
- 「없어요」 → 「없음」
- 마무리 「네」 → 안내
- 「그건 좀 그래요」 → U1
- 「없어요」 → 제출본 생성
