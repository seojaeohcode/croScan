# croScan 프로젝트 이해 정리

> 작성: 2026-10-23 · 근거: `K-조선/` 폴더 전체(파일 18개)를 읽고 정리함
> 실명·전화번호 등 허가서 사진의 개인정보는 옮기지 않았다.

---

## 1. 한 줄 정의

**조선소 내업에서 반장이 올린 비일상(위험)작업 신고서를, 안전팀 승인 전에 AI가 ① 신고서 자체의 위험 포인트 누락을 찾고 ② 시간·공간이 겹치는 다른 작업과의 혼재 위험을 검토해서, 근거와 함께 체크리스트 초안 또는 위험 검토서를 만들어 주는 시스템.** 최종 승인은 안전팀이 하고, 확정된 체크리스트는 반장에게 전달돼 작업 전 교육에 쓰인다.

- AI 위치: **승인 전 필터(A안)**. AI는 검토·추천·초안까지만 하고 승인·지시는 사람이 한다.
- 우선순위: **단건 누락 검토(핵심) > 혼재 위험 검토(croScan 고유 차별점) > 일정 조정안(확장)**.
- 대상: **내업**, 그중 시연 공정은 **선행의장**이다.

## 2. 방향이 어떻게 바뀌었나 (기존 → 최신)

| 구분 | 기존 croScan | 멘토링 후 최신 |
|---|---|---|
| 출발 문제 | 작업 A×B가 충돌하는지 사람이 놓침 | 신고서 한 건의 위험 포인트부터 빠질 수 있음. 여러 건 사이 혼재도 놓침 |
| 분석 단위 | 작업쌍 | **신고서 단건** + 작업쌍 |
| 입력 | PDF·엑셀·이미지 등 업체 작업문서 아무거나 | **작업계획서 / 위험작업허가신고서 / 도면** 세 가지 |
| 대표 시나리오 | 도장 × 용접 | **선행의장 의장품 조립·취부·용접(일상) × 배관 용접부 RT 검사(비일상)** |
| 기술 3번 | 작업 변경 → 재비교 → 변경 기록 저장 | 일정 조정 → **위험 point checklist** → 후속 조율(아직 "?"로 미정) |
| 공간 | GOLAR LNG선 선박 도면, 3D | 선박 도면은 남아 있음. 공장 내 선행의장 작업장 구역은 아직 없음 |

멘토는 "도장과 용접이 동일 장소에서 동시에 진행되는 경우는 드물다"고 했다. 그래서 도장×용접을 대표 혼재 사례로 쓰지 않는다.

## 3. 현장의 실제 업무 흐름 (As-Is)

1. **일상작업**: 파이프·볼트·플랜지 조립처럼 반복하는 정형 작업이다. 건별로 신고하지 않는다.
2. **비일상·위험작업**: 작업반장·조장·협력사가 **사내 전산**으로 위험작업신고서를 작성하고 위험 포인트를 직접 체크한다.
3. **안전팀 승인권자**가 신고서를 검토해 누락 항목과 추가 주의사항을 적고, 필요하면 일정 간섭을 조정한다. 이 단계가 **전산승인(비대면)**이다.
4. 필요하면 **안전요원이 현장 이중점검**(신고서의 `2중점검 대상 Y/N`)과 작업 전 교육을 하고 **안전대면허가**를 낸다.
5. 작업에 착수한다. **안전승인 없이는 작업할 수 없다.**

멘토가 말한 애로사항은 위험항목 누락, 하루 한 팀에 40~50건 수준의 검토량, 반복 행정, 30분~1시간의 착수 대기다. 이 수치들은 멘토가 예로 든 발언이며, 실측 통계가 아니다.

### 멘토 손글씨 메모에서 나온 핵심 (질문내용정리.pdf)
- **절대 병행할 수 없는 작업(혼재작업)**: ① 페인트 작업 ② 용접(TIG 용접) ③ 배관 압력 테스트 ④ 상부·하부 병행작업. 안전관리팀이 집중 단속하며, 혼재가 적발되면 **작업중지**를 내린다. 혼재 규칙의 첫 근거로 가장 쓸 만하다.
- **발표 배경 슬라이드가 필요하다**: 주제를 선택한 배경을 설명해야 한다. 대형 조선 3사(HD현대·한화오션·삼성중공업)의 연도별 안전사고 유형과 중대재해 유형별 사망자 비중(끼임·부딪힘·떨어짐 / 화재·폭발 / 밀폐공간)을 보여 주고, 혼재작업 때문에 큰 중대재해가 생긴다는 점에서 문제 인식을 시작한다.
- **"심사위원은 현업 전문가"**: 현실성 있는 문구가 점수를 받는다.
- **건조 공정 순서**: 철판절단 → 소조립 가공 → 중조립 → 대조립 → 도장공장 → 도크 전체조립 → 선박.
- **내업 작업장**: 소조립·중조립·대조립(혼재 많음), 선행도장. **외업**: 블록 탑재·조립.
- Q4(도면 위치 표시)와 Q5(위험 판단 노하우)에는 "사진 참고"라고만 적혀 있다. 도면보다 실제 현장 사진을 쓰라는 뜻이다.

## 4. 목표 흐름 (To-Be) — 플로우차트 2종

### 4.1 전체 시나리오 플로우차트 (6단계)
```
01 반장 비일상작업 신청 (장소·내용·일시 / 부서·책임자·인원)
   + 일상작업계획서 + 기존 비일상 신청정보 + 위험·안전 기준
02 [AI] 시간·장소 겹침 찾기  ── 겹침 없음 ──────────┐
         │겹침 있음                                    │
03 [AI] 공정별 작업쌍 위험성 검토 (일상×비일상, 비일상×비일상)
         위험조합쌍 데이터의 적용조건·제한·근거와 대조   │
04 [AI] 결과별 자료 생성                              ▼
    통과 → 체크리스트 초안  /  기각·확인 필요 → 위험 검토서
    근거·입력 부족 → 안전팀 확인으로 전달
05 안전팀 검토·보완·최종 판단 → 승인 / 보완(재신청·AI 재검토) / 기각(작업 보류)
06 확정 체크리스트를 반장에게 전달 → 현장 확인·교육 후 착수
※ 시간·장소 겹침 ≠ 위험 확정 · AI 통과 ≠ 작업허가
```

### 4.2 다인 플로우차트 (위험작업 검토 로직, 더 최신·정교함)
- **D-1 승인 전**
  1. 반장 신고: 기존 허가서의 작업·위험·위치·시간을 입력한다.
  2. **모든 신고서 단건 검토**: 반장이 작성한 내용과 작업별 위험 기준을 대조한다. 누락·오기입을 표시하고 필수 체크 목록과 「작업허가 전 추가조치」 초안을 만든다.
  3-1. 공간·시간이 겹치는지 본다. 공간은 동일·인접 구획과 상하 관계까지 포함한다.
  3-2. 위험조합(병행 금지·제한 규칙)에 해당하면 **조정 사유**로, 해당하지 않으면 **주의 표시**로 넘긴다.
  4. 단건과 혼재 결과를 합쳐 **승인 후보 / 보완 필요 / 조정 필요** 세 가지로 나눈다. 셋 모두 사유·근거·보완안을 함께 전달한다.
  5. 안전팀 최종 판단: 승인, 또는 보완·비승인이다. 반려되면 반장이 수정해 다시 신고하고 **처음부터 재검토**한다.
- **D-day 작업 전**
  6. 반장에게 확정 목록을 전달한다(현황판 게시·작업 전 교육·당일 조치 체크).
  7. 현장 확인과 안전팀 대면허가: 이중점검이 Y면 안전요원이 현장을 확인하고, 조치가 미비하면 보완 후 재확인한다. 끝나면 **작업 시작**이다.
  - 확장 기능: 필수 목록과 실제 체크를 자동으로 대조한다.
- 주의할 문구: **"당일 체크란이 비어 있어도 정상"**. 아래 5절에 이유가 있다.

두 차트의 차이는 이렇다. 시나리오 차트는 겹침이 없으면 바로 체크리스트로 가지만, 다인 차트는 **모든 신고서를 먼저 단건 검토**한다. 멘토 피드백(단건 누락이 핵심)에는 다인 차트가 더 맞다.

## 5. 실제 허가서 양식 (HD현대 「기타위험(밀폐)작업 허가서」 사진 2장)

| 영역 | 필드 |
|---|---|
| 식별 | 승인번호(BS22-IV-…), 허가구분(안전현장허가 / 전산허가), 호선/공사, 작업표준(JSP No.) |
| 장소·일시 | 작업장소(공장·작업장·구역·BAY·칼럼), 주간/야간, **일별 시작·종료**(여러 날짜 행) |
| 내용·조직 | 작업내용, 작업부서, 작업책임자, 관리자, 연락처·TRS, 작업인원 |
| 위험 | **유해위험요소/추가전달사항**(작업부서 작성) + **병행여부** |
| 현장 안전조치 | 공지문·경고표지, LOTO, 인화성물질 제거, 통행로 확보, 작업구역 통제, **병행작업 확인(SIMOPS)**, 소화장비, 야간 조명. **당일 작업 시작 전에 기입하며 사전 작성은 금지** |
| 추가정보 | 밀폐구역(출입현황판·감시자·환기·가스측정·조명), 고소작업(출입수단·작업대·안전벨트·생명줄·추락방지), 아르곤가스·수전구역·압력(테스트압력·파이프직경)·작업높이. 대면접수 시에는 작성 금지 |
| 발행 | 허가신청 → 전산승인 → **안전대면허가**(각 일시·서명), PTW 점검 QR, **2중점검 대상 Y/N** |
| 안전요원 | **작업허가 전 추가조치 요청사항**(수기) |

- **사진 1**(유니트4팀, 배관 내부 진입, 6일간, 위험요소 "질식·소음", 2명): 당일 체크란은 **전부 빈칸**이다. 2중점검은 **Y**이고, 하단에 안전요원이 손으로 쓴 추가조치(가스농도 측정·환기·감시자 배치 등)가 있다. 사람이 누락을 보완하는 실제 사례다.
- **사진 2**(대조립21공장 2BAY, 밀폐공간 내부, 4일간, 4명): 위험요소 문장이 구체적이고 체크란도 대부분 체크돼 있다. 2중점검은 **N**이고 전산허가다.

**설계에서 중요한 점**: 당일 체크란은 사전 작성이 금지된 칸이다. 그러니 AI가 승인 전(D-1)에 빈칸을 "누락"으로 잡으면 오탐이다. D-1에 누락을 검토할 대상은 **유해위험요소 기재, 작업 종류에서 필요한 추가정보 분류(밀폐·고소·압력…), 추가조치 초안**이다. 당일 체크와 필수 목록을 대조하는 일은 D-day 확장 기능의 몫이다.

## 6. 입력·출력 설계 (데이터 폴더 이미지)

### 입력 자료 5종
| 입력 | 필요한 정보 | 목적 |
|---|---|---|
| 신규 비일상작업 신청 | 장소·내용·일시·부서·책임자·인원, 첨부 | 검토 대상 식별, 개별 체크리스트 |
| 일상작업계획서 | 작업ID·내용·대상·구역·예정시간·담당팀, 변경 가능 범위·선행작업·장비 | 신고되지 않는 일상작업도 비교에 포함 |
| 기존 비일상 신청정보 | 다른 작업의 ID·내용·위치·시간·조건 | 비일상×비일상 비교 |
| 위험조합쌍·작업별 안전기준 | 공정·작업쌍·적용조건·위험·병행제한·조치·출처·버전 | 위험 검토와 체크리스트 근거 |
| 도면·공간 연결정보 | 구역·갑판·대상·경계·연결 관계 | 같은 공간·위아래·주변·같은 대상 판단 |

### 1차 협력업체용 빈 작업계획서 (현대힘스 양식, 2쪽)
- 1쪽: 작업명, 문서와 수행업체(수행업체·작성자·책임자·호선), 일정·범위(시작·종료·시간대·상태·범위), 위치·연결(작업위치·대상ID·연결정보·도면자료), 인원·장비·사양(인원·담당배치·장비·물질·사양·높이), 1~3단계 작업 순서, 공정 단계·분류 근거
- 2쪽: **선행작업과 혼재 협의**(선행작업·선행조건·혼재작업·방호조치), 예비 확인 기록(공간대상·위험요소·방호상태·가동위험기간·위험종료 × 확인값·시각·유효범위), 출입·대피·이전 상태, 종료와 검토 인계(종료·해제·후속요건·검토승인)

### 시연 시나리오 (선행의장 Z-1, 같은 날, 합성)
| ID | 작업 | 시간 |
|---|---|---|
| R01 일상 | 의장품 조립 | 08:00~10:00 |
| R02 일상 | 의장품 취부 | 09:00~11:00 |
| R03 일상 | 의장품 용접 | 13:00~15:00 |
| **N01 신규 비일상** | **배관 용접부 방사선투과검사(RT)**, 검사 협력사·검사반장·2명 | **10:00~11:00** |

예상 결과는 다음과 같다. N01×R02는 10~11시에 겹치고, RT 통제구역이 작업구역을 포함하므로 조정 사유다. N01×R01은 10:00 경계에서 맞닿는다(경계 처리 규칙 필요). N01×R03은 겹치지 않는다.
다른 합성 예시(작업계획서 합성 정보 이미지)는 "A구역 배관 조립 09~11 × RT 10~12 → 배관 조립을 12시 이후로" 안을 쓴다. 이 경우 출력은 확정 일정, 작업별 주의사항·안전조치, 반장용 교육 체크리스트다.

### 육하원칙 (발표용 요약)
- **왜**: 절차는 있지만, 수기 체크와 하루 수십 건의 검토 때문에 위험 포인트가 빠지거나 착수가 늦어진다.
- **누가**: 입력은 조장·반장, 확인·수정·기각·전산승인은 안전팀 승인권자, 결과 활용은 반장·안전요원이 한다.
- **언제**: 신고 접수 후 승인 전에 검토하고, 변경·재신고 때 다시 검토하며, 작업 전 교육 전에 전달한다.
- **어디서**: 내업의 판넬조립·대조립·선행의장·선행도장이 우선 후보다(멘토 확인 필요).
- **무엇을**: 누락 위험 후보, 안전팀 코멘트 초안, 혼재 위험, 반장용 교육자료를 만든다.
- **어떻게**: AI가 대조·근거·초안을 만들고, 사람이 승인·지시한다.

- 준비 순서: P01 시연 범위 고정(선행의장 일상 3종 + 비일상 1종) → P02 같은 시간·구역 ID로 쓴 세 입력 → P03 작업쌍 조건표와 개별 체크 기준 → P04 정답·반례 평가셋 → P05 사람 결정·전달 이력

## 8. 조선 건조 공정 (교안·흐름도)

- **내업 부문**: 강재 적치 → 전처리 → 절단 → (곡가공) → 소조립 → 판넬조립 → 대조립 → **선행의장**(의장품 취부·용접·조립, SHELTER 안) → **선행도장**(Shop Blasting·Painting)
- **외업 부문**: PE장(Setting·취부·용접·탑재대기) → 운반 → 탑재(골리앗·JIB 크레인) → 의장 → 선체도장 → 진수 → 시운전 → 명명식 → 인도
- 단, 팀 확인 결과 **PE장은 내업·외업 둘 다 해당**한다. 흐름도에는 외업에만 그려져 있다.
- 교안 xls 두 개는 셀 데이터 없이 사진과 도형만 들어 있다. 공정별 실제 사진 6장씩이 있어서, 멘토가 요구한 "도면보다 실제 공정 사진"용 발표 소재로 바로 쓸 수 있다.

## 9. 모순 또는 열린 문제

> 각 문제의 팀 결정 임시안과 멘토 확인 질문은 [croScan_멘토질문_팀결정.md](croScan_멘토질문_팀결정.md)에 정리했다.

1. **당일 체크란 vs 누락 탐지**: 체크란은 사전 작성이 금지돼 있으므로, D-1 누락 탐지 대상에서 빼야 한다(5절).
2. **"의장품 용접"이 일상작업 R03**인데, 멘토는 **TIG 용접**을 절대 병행 불가 작업으로 꼽았다. 용접 종류(TIG·CO2 등)를 구분하는 필드가 필요한지 확인해야 한다.
3. **RT 시간이 예시마다 다르다**: 시연 예시는 10~11시, 합성 계획서 예시는 10~12시다. 시연 데이터를 하나로 맞춰야 한다.
4. **R01이 10:00에 끝나고 N01이 10:00에 시작한다**: 경계 규칙(반개방 구간 여부)을 미리 정의해야 한다(분기 B05).
5. **최신 MVP 3번의 "후속 조율 기능"이 "?"로 남아 있다**: 정의가 필요하다. 후보는 변경안 재검토와 다른 협력업체·후속공정 영향 확인이다(Q6·Q7 질문의 연장).
6. **공간 데이터가 맞지 않는다**: MVP 이미지와 A08은 선박 평면도(GOLAR) 기반인데, 시연 공정은 공장 내 선행의장 Z-1이다. 작업장 구역 정의가 없다.
7. **RT 방사선 통제범위가 없다**: 임의 반경을 계산하지 않고, 입력된 통제구역 값을 사용하기로 했다(T04).
8. ~~7공정 명칭이 확정되지 않았다~~ → **해결**: 7번째는 선체도장이다. 7공정 = 판넬조립·대조립·선행의장·선행도장·PE장·탑재·선체도장.
9. **수치를 주장할 때 주의해야 한다**: 40~50건/일, 30~60분 대기, 내업:외업 60:40, 도장×용접 5% 미만은 모두 멘토 발언이며 통계가 아니다.

## 10. 개발 관점 요약 — 1차 MVP 범위

1. **신고서 입력/불러오기**: 6개 기본정보(장소·내용·일시(일별)·부서·책임자·인원)와 위험요소 텍스트, 추가정보 분류. 문서 업로드를 쓸 때만 OCR이 필요하다.
2. **기준 데이터**: 선행의장 한정. 작업종류별 위험 포인트·확인질문·조치·근거(R02), 병행 금지 규칙(멘토가 말한 4종 + 105 후보 재검토 = R01)을 쓴다.
3. **단건 검토 엔진**: 신고 내용과 작업별 기준을 대조해 누락·오기입 후보와 근거를 내고, 「작업허가 전 추가조치」 초안을 만든다.
4. **혼재 검토 엔진**: 일별 시간구간 겹침, 구역 관계(동일·인접·상하·통제구역 포함), 위험조합 규칙 순서로 판정하고 조정 사유 또는 주의를 표시한다.
5. **결과 3분류**: 승인 후보 / 보완 필요 / 조정 필요. 미확인 상태는 따로 둔다.
6. **안전팀 검토 화면**: 후보별로 확인·수정·기각하고 이력을 남긴다. 승인·보완·비승인과 반려 시 재신고 루프를 지원한다.
7. **확정 출력**: 반장용 체크리스트·교육자료, 현황판 보기.
8. 이후 확장: 일정 변경안과 전체 재검토, 사진·3D 시각화, D-day 당일 체크 자동 대조, 사내 시스템 연동.
