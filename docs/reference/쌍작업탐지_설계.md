# croScan 쌍작업 위험탐지 설계 (안전관리자 시점)

> 2026-10-27 작성. 코드: `croScan_app/server/pairs.py`(엔진), `server/pair_rules.json`(규칙표 16개), `tools/check_pairs.py`(채점).
> 화면: 안전관리자 → 「쌍작업 위험탐지 시작」. GPT(Codex)는 검토만 했다(로직 검토 2회).

## 1. 무엇을 하나

- **대상**: 하루치 서류(허가서 = 비일상 10건, 작업계획서 = 일상 40건)에서 만들 수 있는 쌍은 다음과 같다.
  - 일상×비일상 400쌍
  - 비일상×비일상 45쌍
  - 합계 445쌍
  - 일상×일상은 사용자 요청 범위 밖이다.
- **판정**: 규칙만 쓴다(LLM 없음). 같은 입력이면 늘 같은 결과가 나온다.
- **출력**: 쌍마다 우선순위(1·2·3순위)와 설명(XAI)이 붙는다. 경보하지 않은 근접 쌍에도 그 이유를 붙인다.

## 2. 판정 6단계 (조사자 원칙 그대로)

| 단계 | 조사자 원칙 | croScan |
|---|---|---|
| 1 | 서로 다른 작업건인가 | 문서 1건 = 작업 1건. 자기 자신과는 쌍을 만들지 않는다 |
| 2 | 시간이 겹치나, 잔류위험이 남나 | 위험 단계의 시간으로 본다(인양은 실제 이동 시각, 크레인 단계는 적힌 시각부터). 앞 작업이 끝난 뒤 같은 날 이어지는 작업은, 잔류위험이 없어졌다는 확인 기록이 없으면 확인 대상이다 |
| 3 | 두 작업을 잇는 경로 | 규칙 16개(전달방식 7가지: 낙하·이동·불티·가스·공유설비·공통지지·접근방해) |
| 4 | 실제로 노출되나 | 원인 작업 → 노출 작업. 인원 0명이면 제외하고, 인원 미상이면 노출 2 이하로 둔다 |
| 5 | 원인 → 노출 → 사고 설명 | 규칙의 3단 문장(조건 → 원인 → 사고). "~할 수 있다"로 쓴다 |
| 6 | 모르는 값은 「확인 필요」 | 시간·위치·인원이 없으면 노출 1이다. 안전하다고 보지 않는다 |

**같은 BAY는 위험이 아니다.**
- 같은 칼럼 주소도 '가능'(노출 2)일 뿐이다.
- '확인'(노출 3)이 되려면 다음 중 하나가 있어야 한다.
  - 같은 블록
  - 명시된 이동 경로
  - 같은 설비 ID
  - 위아래 관계가 적힌 답변이나 높이

## 3. 작업 성질 읽기 (두 서류 공통)

- **글을 구절 단위로 나누고, 실제로 하는 일(행위)만 본다.**
  - 「화기작업 여부 확인」, 「용접부 검사」, 「용접기 점검」은 화기로 보지 않는다.
  - 「OH-21-03 사용, OH-21-02 미사용」은 구절마다 부정을 따로 본다.
  - 연결정보 줄에 적힌 크레인만으로는 사용으로 보지 않는다.
- **읽어 내는 성질**: 화기, 유기용제(수성·불연 도장은 제외), 밀폐 진입, 불활성가스, 크레인 인양(ID), 크레인·전원 정전(ID), 전원 사용(ID), 높은 곳 절단·해체, 압력시험, 방사선, 차량, 고소작업대, 블록 ID, 높이(최저·최고).

## 5. 위험도와 우선순위

- **강도 S**
  - 3: 사망·중대재해 가능
  - 2: 중상·건강장해
- **노출 E**
  - 3 = 확인: 같은 시간에, 같은 블록·경로·설비로 서류상 이어진다.
  - 2 = 가능: 칼럼 주소만 같다. 또는 사건이 하나 더 있어야 경로가 생긴다. 또는 인원이 미상이다.
  - 1 = 미확인: 시간·위치 정보가 없다. 또는 잔류위험이 없어졌다는 확인 기록이 없다. 또는 바로 옆 칼럼이다.
- **우선순위**
  1. **1순위 즉시 조정**: 금지 조합이 노출 3으로 확인된 경우. 일정을 바꾸거나 한쪽을 멈춘 뒤 승인한다.
  2. **2순위 조건부 병행**: 강도×노출이 6 이상인 경우. 통제·유도·차단 조치를 확인한 뒤 병행한다.
  3. **3순위 확인 필요**: 강도×노출이 3~5인 경우. 작업반장·업체에 확인한 뒤 판단한다.
  4. 3 미만은 경보하지 않는다.
- 한 쌍에 이유가 여럿이면, 가장 높은 순위의 이유가 대표가 되고 나머지는 「다른 이유」로 보인다.

## 6. 설명(XAI) 한 장의 구성

1. 한 줄 요약(조건 → 원인 → 사고)
2. 왜 위험한가: 3칸 그림
3. 두 작업: 원인·노출 카드, 문서 열기
4. 언제 겹치나: 시간 막대
   - 겹치는 구간은 빨강이다.
   - 잔류위험 구간은 빗금이다.
   - 추정 인양 구간은 점선이다.
5. 위험도: 3×3 행렬, 노출 이유
6. 조치 제안
7. 확인할 것(작업반장에게 물을 질문)
8. 판정 근거: 문서 · 칸 · 값
9. 참고 사례·법(이 작업의 사고가 아님)
10. 같은 쌍의 다른 이유(각각 근거·조치·질문 포함)

## 7. 시연 하루(2026-10-29) 결과

- **걸러진 과정**: 445쌍 → 시간이 겹침 152 → 그중 같은 BAY 32(위치 미상 5쌍은 따로 센다) → 위험 전달 경로 11, 여기에 확인 필요 2(잔류위험 1, 위치 미상 1)를 더해 **13쌍**이다.
- **우선순위**: 1순위 8 / 2순위 3 / 3순위 2이다.
- **P13 (3순위)**: 9488 크레인 제어반 정전 작업은 칼럼 위치가 적혀 있지 않다. 그 시간에 같은 3BAY에서 WP-26 가용접(화기)이 진행된다. 그래서 '같은 곳인지 확인 필요'로 남겼다.
- **반례 시험**: `tools/check_pairs_cases.py` 14/14 통과. GPT 검토에서 나온 경우들이다(잔류위험 시간 제한 없음, 시간 미상, 인원 0명, 가스 계통, 일정 불일치, 부정 표현, 공통지지, 반대 방향 낙하, 겹침 조각, 야간).
- **정답표와 비교**(정답표는 채점에만 쓰고 규칙은 읽지 않는다)
  - 범위 안 11쌍을 모두 찾았다. 그중 9쌍은 우선순위까지 같다.
  - C08·C09는 원칙에 따라 1순위로 판정했다. 인양물 아래 출입 금지, 정비 중 설비 사용 금지 조합이기 때문이다. GPT 검토도 동의했다.
  - 근접 5쌍은 모두 경보하지 않았다. 이유도 정확하다. 예: N04 "전원이 달라 이어지지 않음(MCC-4 정전 · MCC-5 사용)".
  - 정답표 밖 1쌍(P12)은 3순위다. 밀폐 작업이 끝나고 40분 뒤 같은 블록을 반출하는데, 퇴실 확인 기록이 없다. 조사자료 P02 유형이다.

## 8. 한계

- 칼럼은 주소일 뿐이고, 실제 외곽·높이·개구부는 서류에 없다. 그래서 같은 블록이 아니면 '가능' 이상으로 확정하지 않는다.
- 설비 별칭(「천장 3호기」 등)은 설비 대장이 있어야 같은 설비로 묶을 수 있다.
- 잔류위험은 시간이 지나도 저절로 사라진다고 보지 않는다. 같은 날 뒤에 이어지는 작업은 확인 기록이 생길 때까지 「확인 필요」로 남는다.
- 최종 판단과 조정은 안전관리자가 한다.
