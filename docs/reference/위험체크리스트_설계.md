# croScan 위험 체크리스트 (작업반장 시점) 설계

2026-10-27 · Claude·Codex(GPT) 공동 작성 · 관련 코드 `croScan_app/server/checklist.py`, `checklist_spec.json`, `submissions.py`, `web/app.js` 4·5단계

## 0. 한 줄 요약

croScan은 **허가서만으로**(허가서 값 + 확인 질문(멀티턴)의 답 = 추가정보) **위험 체크리스트 초안**을 만든다. 작업계획서는 근거로 쓰지 않는다. 작업반장은 항목마다 「해당 / 해당 없음 / 안전팀 확인」을 눌러 확인하고 준비할 안전조치를 고른다. 그런 다음 **서류 3가지**(허가서 원본+추가검토서, 작업계획서, 위험 체크리스트)를 한 번에 안전팀에 제출한다. 여기서부터는 안전관리자 시점이다.

## 1. 흐름 (5단계)

| 단계 | 하는 일 | 결과 |
|---|---|---|
| 1 허가서 올리기 | 종류 5개 중 고르기, PDF 올리기 | 양식 칸 읽기 |
| 2 허가서 검토 | 확인 질문(멀티턴), 칸 고치기 | 추가검토서(2쪽) |
| 3 작업계획서 확인 | 계획서 올리기, 고치기, 확인 | 작업계획서 수정본 |
| **4 위험 체크리스트** | croScan 초안 확인, 해당 여부·준비할 조치 | 위험 체크리스트 PDF |
| **5 제출** | 한눈에 확인한 뒤 「안전팀에 제출」 | 제출 번호 + 서류 3가지 |

**근거는 허가서뿐이다 (사용자 결정, 2026-10-27).** 현장에서는 생산 쪽(작업반장·생산부서)이 허가서를 올리면서 1차 위험 체크리스트를 함께 올린다. 그래서 체크리스트는 그 허가서와, 그 허가서에 대해 반장이 답한 추가정보(병행작업, 높이, 가스, 진입 방식 등)로만 만든다. 다른 작업(작업계획서)과의 겹침은 안전관리자 단계에서 본다. 작업반장은 처음부터 쓰지 않고 **확인만** 한다.

## 2. 전날 계획이지 당일 확인이 아니다

- 허가서 5번 「현장 안전조치 및 추가정보」는 **작업 당일 시작 전 체크(사전 작성 금지)** 칸이다. croScan은 그 칸을 절대 채우지 않는다. 검사 도구가 허가서 값이 바뀌지 않았음을 확인한다.
- 체크리스트의 조치는 모두 "…할 예정" 문장이다. "실시함·완료함"은 쓰지 않는다. 명세 검사와 PDF 검사에서 금지어를 확인한다.
- 당일 칸과 연결되는 조치에는 「당일 허가서 5번에서 확인」 표시를 붙인다. 안전관리자가 당일에 같은 항목을 찾을 수 있게 하려는 것이다.

## 4. 처음 상태를 정하는 규칙 (prefill)

- 상태는 해당(yes) / 해당 없음(no) / 확인 필요(check) 세 가지다. **기본은 확인 필요**다. croScan은 "해당 없음"을 짐작하지 않는다.
- 규칙이 보는 신호:
  - 허가서 머리 칸 체크(`head`)
  - 허가서 글(`text`): 작업내용, 유해위험요소, 장소
  - 확인 질문의 답(`answer`): 예) H2 공법, CF1 진입 방식, B3 병행작업
  - 정리된 값(`eff`): 높이 2m 이상, 병행여부, 위치 층
- 글과 답은 멀티턴과 같은 읽기(`augment.said`)를 쓴다. "가스 안 씀"(부정), "다른 작업 없으면"(조건), "아마"(추정)는 언급으로 치지 않는다.
- 해당 규칙과 해당 없음 규칙이 둘 다 맞으면(예: 허가서 병행 N인데 답은 "있음") **확인 필요**로 두고 양쪽 근거를 보여 준다.
- 화면에는 항상 근거를 보여 준다. 예: "croScan이 「해당」으로 본 근거: 허가서 「용접·용단」 칸이 체크되어 있음".

## 5. 작업반장 화면 (4단계)

- 항목마다 카드 하나. 큰 3칸 버튼(해당 / 해당 없음 / 안전팀 확인, 48px 이상, 장갑 모드 64px)이 있다.
- **한 번 눌러야 「확인함」**이다. 이미 맞게 골라져 있어도 눌러서 확인한다. 위쪽 고정 막대에 확인 수와 상태별 수를 보여 준다.
- 해당이면 준비할 조치를 체크한다. 처음 「해당」을 누르면 법정 조치가 미리 골라진다. 메모는 선택이다.
- 「위험요인 직접 추가」로 목록에 없는 위험을 넣는다. 「체크리스트 PDF 미리 보기」로 안전팀이 받을 모양을 본다.
- 앞 단계에서 허가서를 고치거나 답을 바꾸면 다시 열 때 croScan이 초안을 새로 만든다. **작업반장이 손댄 항목은 그대로** 두고, 손대지 않은 항목만 새 판단을 따른다.
- 임시저장: 체크리스트 선택도 이 기기에 저장한다. 같은 허가서를 다시 올리면 「이어서 하기」로 되살린다.

## 6. 제출 (5단계)과 안전관리자에게 가는 것

- 「안전팀에 제출」은 서버에 제출 1건을 만든다(`data/submissions/CS-날짜-임의10자`).
  - `permit.pdf`: 원본 + 추가검토서
  - `plans.pdf`: 작업계획서 수정본
  - `checklist.pdf`: 위험 체크리스트
  - `meta.json`: 승인번호, 위험시간대, 장소, 답 수, 미답 질문 수, 체크리스트 해당/확인 필요/해당 없음 수, 확인 안 한 항목 수, 계획서 확인 수, 읽지 못한 파일
- 확인하지 않은 체크리스트 항목이 있으면 제출 전에 한 번 묻는다. 막지는 않고, 안전팀에 "확인 안 함"으로 간다.
- 같은 작업을 고쳐서 다시 제출하면 앞 제출은 「대체됨」으로 표시하고 지우지 않는다.
- 제출 번호가 문서의 열쇠이므로 추측할 수 없게 만든다(32자 중 10자). 목록 조회는 아직 없다. 안전관리자 화면에서 권한과 함께 만든다.
- 전산(HI-SES) 등록은 지금처럼 직접 한다.

## 10. 한계

- 조사자료의 위험 중 고른 것이다. 모든 세부 위험을 담은 위험성평가가 아니다. 빠진 위험은 「직접 추가」로 넣는다.
- 작업계획서와의 대조는 하지 않는다(허가서만으로 만듦). 다른 작업과의 겹침은 안전관리자 단계에서 본다.
- 허가서에 「추가전달사항」 칸이 따로 없다. 그 내용은 「유해위험요소」 칸에 함께 적혀 있어서 그 칸을 읽는다.
- 법정 조치 선택은 제안일 뿐이다. 이행이나 승인을 뜻하지 않는다.

## 11. 허가서만으로 만들기 (2026-10-27, 사용자 지적)

- 그때까지 작업계획서가 쓰인 곳은 한 군데였다. 「병행·혼재작업」 항목에서 같은 날짜의 계획서가 있으면 "해당 없음"이 되지 않게 막는 규칙이다. 이 규칙을 지웠다.
