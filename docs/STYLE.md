# 문서 작성 규칙 (croScan 저장소 docs/)

- 한국어. 짧은 문장, 쉬운 낱말. 한 문장에 한 가지.
- 독자: croScan을 처음 보는 팀원(개발자·기획·발표 담당). 코드를 몰라도 앞부분만 읽으면 무엇을·왜 하는지 알고, 개발자는 뒷부분에서 어디를 고치면 되는지 안다.
- 각 문서 첫머리: 제목, 한두 문장 요약, 「이 문서에서 알 수 있는 것」 3~5줄, 목차.
- 구조: 「무엇을」 → 「왜(현장·자료 근거)」 → 「어떻게(흐름·규칙)」 → 「코드 어디」 → 「시험」 → 「한계」.
- 표와 Mermaid 다이어그램을 적극 쓴다(GitHub가 그린다). 다이어그램 글자는 한국어.
- 코드 위치는 저장소 기준 상대 링크: [`server/pairs.py`](../server/pairs.py). 함수 이름은 `profile()`처럼.
- 수치는 지금 코드 기준(쌍 규칙 36, 체크리스트 86항목, 연구 ref 73/81, 시험 check_* 34종). 확인하지 않은 수치·효과는 쓰지 않는다. 추정은 「추정」, 시연 자료 결과는 「시연 자료 기준」이라고 쓴다.
- 과장 금지: croScan은 승인·일정·작업 차단을 하지 않는다. 판단은 사람(작업반장·안전관리자)이 한다. 「AI가 판단」이라고 쓰지 않는다.
- 현장 용어는 처음 나올 때 풀어 쓴다(예: 판정보류 = 확인이 필요해 3순위로 남긴 경보).
- 비밀 값(.env, 토큰, 키)과 모델 파일은 쓰지 않는다.

## 쉬운 문장 (2026-11-01 추가)

- 문장은 초등학생도 이해할 만큼 쉽게 씁니다. 어려운 것은 문장이 아니라 용어여야 합니다.
- 안전 용어(화재감시자, LOTO, 밀폐공간, 잔류위험 …), 현장 용어(BAY, 칼럼, 블록, 족장 …), AX·개발 용어(LLM, API, 규칙, 캐시 …)는 그대로 씁니다. 처음 나올 때 한 번만 쉽게 풉니다.
- 한 문장에 한 가지. 주어를 분명히("croScan이 …", "반장이 …"). 문장이 두 줄을 넘으면 나눕니다.
- 번역투를 쓰지 않습니다: `~를 통해` → `~로`, `~에 있어서` → `~에서`, `~에 의해 만들어진` → `~가 만든`, `~되어진다` → `~된다`, `~을 가지고 있다` → `~이 있다`.
- 빈말을 쓰지 않습니다: 「결론적으로」 「주목할 만하다」 「~할 필요가 있다」 「~라는 점」 「다음과 같다」.
- 같은 어미가 줄줄이 이어지지 않게 합니다. 「~할 수 있다」가 겹치면 일부만 바꿉니다(뜻의 강도는 그대로).
- 굵은 글씨·따옴표·괄호 병기는 꼭 필요할 때만.
- 참고: 한국어 AI 문체 교정 규칙 [im-not-ai](https://github.com/epoko77-ai/im-not-ai)의 quick-rules.
